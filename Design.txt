# 제목: 함락! 무한의 지옥철

플레이어는 무한히 반복되는 지하철에서 무작위로 만나는 캐릭터를 상대로 카드를 사용하는 덱빌딩 게임을 진행한다. 한 캐릭터를 선택해 승패가 결정될 때까지의 플레이를 하나의 세션, 세션 안에서 카드로 겨루는 과정을 전투라고 부른다.

캐릭터의 *저항*을 0 이하로 만들면 함락에 성공한다. 제한 턴 안에 저항을 0 이하로 만들지 못하거나 플레이어의 *은폐*가 0 이하가 되면 실패한다. 같은 해결 시점에 저항과 은폐가 모두 0 이하가 되었다면 승리를 우선한다.

매 턴 플레이어가 선택한 카드를 먼저 해결하고 캐릭터가 미리 선택한 카드를 해결한다.

하나의 세션 제한은 최소 7턴에서 최대 12턴 사이에서 정하며, 세션 시작 전에 "남은 역" 등의 형태로 공개한다. 정확한 추첨 분포는 알파 전 결정한다.

플레이어는 게임 시작 시 총 10회의 카드 드래프트를 진행한다. 매 드래프트마다 무작위 카드 3장 중 하나를 선택한다. 덱 구성 후에는 전투 대상 3명이 무작위로 나타나며 이 중 한 명을 선택해 첫 세션을 시작한다. 대상 선택 화면에는 캐릭터의 저항, 시작 무드, 공개된 특징, 주요 행동 태그 등 덱과의 상성을 판단할 수 있는 정보가 표시된다.

플레이어와 캐릭터는 매 턴 기본적으로 세 장을 드로우하며 최대 손패는 다섯 장이다. `baseDrawCount`와 `maxHandSize`는 서로 분리하고 캐릭터별 정의나 효과에 따라 달라질 수 있다.
턴 시작시 각자의 기본 드로우 수만큼 최대 손패를 넘지 않는 범위에서 카드를 드로우하고, 턴 종료시 사용하지 않은 카드는 모두 버린다. 카드의 드로우 효과는 해결 즉시 현재 턴 손패에 카드를 추가하되 최대 손패를 넘기지 않는다.
세션 시작 시 플레이어와 캐릭터 덱은 저장 상태의 고정 시드와 난수 커서를 사용해 각각 섞는다. 같은 시드와 같은 입력은 언제나 같은 덱 순서를 만든다.
덱에서 드로우 할 카드가 부족해지면 버려진 카드를 덱에 섞어 넣은 후 마저 드로우 한다.
이번 턴에 사용한 카드는 턴 종료 전까지 별도의 사용 카드 영역에 놓이며 같은 턴의 드로우에는 포함되지 않는다. 턴이 종료되면 제거 카드와 계획 슬롯에 놓인 카드를 제외하고 버린 카드 더미로 이동한다.
캐릭터들은 각자의 카드 덱과 특징을 가지고 있으며 매 턴 카드를 사용해 저항을 회복하거나 플레이어의 은폐를 감소시킨다. 보유한 특징에 따라 특정 행동 태그의 효과를 무력화하거나 증가·감소시킬 수 있다.

플레이어 카드는 기본 은폐 비용과 기본 저항 피해를 가질 수 있다. 카드 선언 시 환경과 퍽 등을 반영한 최종 은폐 비용을 먼저 지불한 뒤 카드 효과를 해결한다. 최종 비용은 0보다 작아질 수 없으며, 현재 은폐가 최종 비용보다 커야 카드를 사용할 수 있다. 비용 지불만으로 은폐가 0이 되는 카드는 사용할 수 없다.

은폐에는 최대값을 두지 않는다. 은폐 비용, 외부 효과에 의한 은폐 손실과 은폐 회복은 서로 다른 사건으로 기록한다.

캐릭터와 플레이어는 기본적으로 한 턴에 하나의 주 행동 카드만 사용한다. `연계` 메커니즘이 있는 카드는 주 행동을 소비하지 않는다.

특정 조건에서 나중에 효과가 발동하는 계획 슬롯이 캐릭터와 플레이어에게 하나씩 존재한다. 계획은 일회성 또는 여러 번 발동하는 효과일 수 있지만 각 진영은 동시에 하나만 배치할 수 있다.

모든 계획 카드는 발동 횟수, 지속 턴 또는 별도의 폐기 조건 중 하나 이상을 반드시 가진다. 자동으로 발동한 계획 효과는 새로운 카드 사용으로 취급하지 않으며 다른 계획을 재귀적으로 발동시키지 않는다. 새로운 계획 카드를 사용하면 기존 계획 카드는 버린 카드 더미로 이동한다. 성공적으로 발동해 남은 충전이 0이 되면 즉시 버리고, 배치 다음 턴부터 턴 종료에 지속시간을 감소시켜 0이 되면 버린다. 완료 상태에는 충전이나 지속시간이 0인 점유 계획을 남기지 않는다.

상대 계획 슬롯이 차 있다는 사실은 공개하고, 지속 턴이 정해진 계획이라면 남은 지속 턴도 공개한다. 계획 이름, 효과와 발동 조건은 실제 발동하거나 별도의 관찰 효과로 확인하기 전까지 비공개다. 한 번 발동해 공개된 계획은 슬롯에서 벗어날 때까지 공개 상태를 유지한다. 남은 발동 횟수는 계획이 공개된 뒤에도 숨기며, 이를 명시적으로 확인하는 별도 효과가 있을 때만 보여준다. 발동하지 않고 만료되거나 교체된 계획은 공개하지 않는다.

## 한 턴의 진행과 트리거 타이밍

1. 세션 시작: 환경, 캐릭터 특징, 플레이어 퍽의 세션 시작 효과를 해결한다.
2. 턴 시작: 턴 시작 효과를 해결하고 플레이어와 캐릭터가 각자의 기본 드로우 수만큼 최대 손패를 넘지 않게 드로우한다.
3. 캐릭터 행동 선택: 캐릭터는 이번 턴에 사용할 연계 카드와 주 행동 카드의 순서를 미리 선택한다. 플레이어에게는 주 행동 카드의 행동 태그만 공개한다.
4. 플레이어 선택: 플레이어는 전투 UI에서 사용할 카드와 연계 순서를 선택한다. 일반 카드 효과, 숨은 트리거와 수치 변화는 판정하지 않는다. 다만 같은 턴 선택을 확장하는 선언형 드로우는 권위 상태와 RNG를 바꾸지 않는 결정적 `turnDraft` 프리뷰로 보여주며 전송 전까지 선택을 수정할 수 있다.
5. 수동 전송: 별도의 턴 종료 버튼을 두지 않는다. 사용자가 내용이 비어 있는 RisuAI 입력의 전송 버튼을 직접 누르는 순간 선택이 확정된다. 카드가 없으면 아무 카드도 사용하지 않는 패스, 연계 카드만 있으면 그 카드를 해결한 뒤 주 행동 패스로 정상 진행한다.
6. 턴 판정: 엔진은 플레이어 카드, 캐릭터 카드와 턴 종료 효과를 아래의 기계적 순서로 해결한 뒤 결과를 대기 트랜잭션으로 보관한다. 현재 전투 상태는 아직 변경하지 않는다.
7. 정상 LLM 요청: RisuAI가 프리셋, 캐릭터 설정과 활성 로어북을 포함해 만든 정상 요청에 확정된 턴 사건과 묘사 지침만 추가한다. Lua가 LLM을 직접 호출하거나 전송을 자동화하지 않는다.
8. 출력과 상태 반영: 정상적인 LLM 출력이 도착하면 대기 결과를 현재 전투 상태에 한 번만 반영하고, 캐릭터 카드와 수치 결과를 장면 묘사와 갱신된 UI에서 공개한다.
9. 세션 종료: 반영된 저항, 은폐 또는 제한 턴으로 승패가 결정되었다면 세션 종료 효과를 해결한다.

턴 판정 안의 카드 해결 순서는 다음과 같다.

1. 플레이어가 선택한 카드를 순서대로 선언한다.
2. 각 카드 때문에 발동할 카드 사용 전 효과를 확인한다. 간파 카드라면 이 카드와 파생 효과에 반응한 상대 계획을 먼저 억제하고, 나머지 계획과 카드 사용 전 효과를 해결한다.
3. 카드의 기본 효과와 무드 추가효과를 해결한다.
4. 카드 사용 후 효과를 해결한다.
5. 연계 카드가 남아 있다면 같은 과정을 반복하고, 주 행동을 해결하면 플레이어 행동을 끝낸다.
6. 캐릭터가 미리 선택한 카드들을 같은 순서로 공개·해결한다.
7. 턴 종료 효과, 카드 영역 이동, 공통 무드 판정과 승패 판정을 해결한다.

퍽, 특징, 계획, 환경효과는 다음의 트리거 타이밍 중 하나 이상을 사용한다.
* 세션 시작
* 턴 시작
* 캐릭터 행동 태그 공개
* 플레이어 카드 사용 전
* 플레이어 카드 사용 후
* 캐릭터 카드 사용 전
* 캐릭터 카드 사용 후
* 턴 종료
* 세션 종료

카드 사용 전 트리거는 선언된 카드의 효과보다 먼저 해결되며, 카드 사용 후 트리거는 카드의 기본 효과와 무드 추가효과가 모두 해결된 뒤 발동한다.

카드 한 장과 그 카드로 발생한 사용 후 트리거까지 해결한 시점에 저항과 은폐를 확인한다. 저항 또는 은폐가 0 이하가 되었다면 남아 있는 연계 및 캐릭터 행동을 중단하고 턴 종료와 세션 종료 절차로 이동한다. 같은 확인 시점에 둘 다 0 이하라면 승리로 처리한다.

같은 타이밍에 여러 계획·특징·퍽·환경 효과가 발동할 때의 우선순위와 수치 보정 순서는 구현 전에 별도로 확정한다.

## 무드

저항과 은폐와 별도로 `거절-의심-무시-혼란-순응`의 다섯 단계 무드가 존재한다. 카드는 특정 무드에서 패널티나 추가효과를 얻을 수 있지만 모든 무드에 효과를 가질 필요는 없다.

기본 시작 무드는 `무시`이며 캐릭터 설정이나 특징으로 변경할 수 있다. 무드는 승패를 직접 결정하지 않으며, 순응 상태가 항상 플레이어에게 유리한 것도 아니다.

무드는 턴 전체의 실제 결과로 한 번 계산한다.

```text
저항 성과 = 턴 시작 저항 - 턴 종료 저항
은폐 소모 = max(0, 턴 시작 은폐 - 턴 종료 은폐)
무드 성과 = 저항 성과 - 은폐 소모
```

카드 원문이 아니라 환경, 계획, 특징과 퍽을 모두 반영한 실제 시작·종료 수치를 사용한다. 은폐 회복은 같은 턴의 은폐 감소를 상쇄할 수 있지만 그 자체로 무드 성과를 양수로 만들지는 않는다.

기본 경계는 다음과 같다.

```text
거절 ←5→ 의심 ←4→ 무시 ←4→ 혼란 ←5→ 순응
```

- 양수 기준 이상이면 순응 방향으로 한 단계 이동한다.
- 음수 기준 이하이면 거절 방향으로 한 단계 이동한다.
- 공통 판정으로는 한 턴에 최대 한 단계만 이동한다.
- 초과 성과는 다음 턴으로 이월하지 않는다.
- 카드가 직접 무드를 변경하거나 고정했다면 해당 턴의 공통 판정을 생략한다.
- 세션이 종료되었다면 무드 판정을 생략한다.

## 카드 태그와 메커니즘

각 카드는 의도나 행동을 분류하는 행동 태그를 반드시 하나 가진다. 메커니즘은 0개 이상 가질 수 있으며 엔진은 개수를 제한하지 않는다. 조합의 복잡도와 파워는 카드 설계에서 관리한다.

- 메커니즘
* 연계: 이 카드는 주 행동을 소비하지 않음
> 연계 카드는 상대에게 접근하거나 기회를 엿보는 등의 소극적인 준비 행동을 표현한다. 드로우, 정보 확인, 계획 보조, 다음 카드의 조건부 강화 등을 주된 효과로 삼고 저항이나 은폐를 크게 변화시키는 독립적인 행동은 지양한다.
> 연계 카드가 여러 장 사용되더라도 LLM이 각각을 별개의 큰 사건으로 묘사하지 않도록 각 카드의 묘사는 서로 결합 가능한 짧은 준비 행동으로 작성한다.
* 제거: 이 카드는 한번 사용되면 이번 세션에서 더 이상 등장하지 않음
> 주로 강력한 효과를 가지는 카드에 적용
* 계획: 사용 시 계획 슬롯에 놓이며 데이터에 기록된 조건을 만족하면 발동
* 간파: 이 카드와 이 카드에서 파생된 효과 때문에 발동할 상대 계획을 이번 해결에서만 억제

간파는 계획의 이름, 조건과 효과를 공개하지 않는다. 억제된 계획은 발동 횟수나 충전을 소비하지 않고 숨겨진 상태를 유지하며, 지속시간은 정상적으로 흐른다. 턴 시작·종료 등 해당 카드와 무관한 계획은 정상적으로 발동한다.

- 행동 유형에 따른 태그
* 플레이어 행동
> 관찰, 접근, 기만, 위협, 접촉, 유린 등
* 캐릭터 행동
> 회피, 차단, 경계, 협박, 폭로 등

플레이어와 캐릭터의 행동 태그는 서로 동일할 필요가 없다. 계획은 카드 데이터에 자신이 반응할 사건이나 상대 행동 태그를 별도로 기록한다. 무드 추가효과와 LLM 묘사용 정보는 행동 태그에 포함하지 않고 별도의 필드로 관리한다.

# LLM 장면 묘사
각 카드 DB에는 규칙 설명과 분리된 LLM용 행동 및 생각 묘사를 기록한다. LLM에게는 카드 이름이나 "카드를 사용했다"는 사실을 전달하지 않고, 카드가 의미하는 실제 행동, 생각, 반응과 엔진이 계산한 최종 결과를 전달한다.

RisuAI 입력창은 CSS로 입력할 수 없게 만들고 내용은 항상 비워 둔다. 플레이어의 게임 입력은 전투 UI에서 선택한 카드뿐이며, 사용자는 정상 프리셋 요청을 시작하기 위해 전송 버튼만 직접 누른다.

카드 첫 클릭은 상세 표시, 같은 카드 두 번째 클릭은 사용 등록, 등록 카드 재클릭은 취소다. 눈치보기는 등록 즉시 권위 상태를 바꾸지 않는 고정 프리뷰로 1장을 보여준다. 눈치보기와 원래 손패 카드 또는 프리뷰 카드를 함께 등록하면 둘 다 사용한다. 프리뷰 카드까지 등록한 뒤 다른 원래 손패 카드를 등록하면 speculative 가지를 모두 취소하고 마지막 카드만 사용한다.

턴 결과는 모델 요청 전에 결정하지만 출력 전에는 공개하지 않는다. 생성 실패나 재생성 시 같은 턴 결과를 재사용하며 카드 효과와 난수를 다시 처리하지 않는다.

계획이나 조건부 카드는 배치, 발동, 만료 상황에 서로 다른 묘사가 필요할 수 있으므로 사건별 묘사를 가진다. 다만 상대의 미공개 계획을 배치할 때는 카드별 묘사를 LLM 요청에 넣지 않고, 계획 슬롯이 생겼다는 사실만 나타내는 공용의 중립적 행동을 전달한다. 계획의 정체를 아는 관점에서만 카드별 배치 묘사를 사용할 수 있다.
* 공개된 사용 또는 배치 묘사: 계획을 세우거나 행동을 준비하는 장면
* 발동시 묘사: 조건이 충족되어 실제 효과가 나타나는 장면
* 실패 또는 만료시 묘사: 필요한 카드에 한해서만 사용

예시: 접촉 태그에 반응하는 캐릭터 계획을 미공개로 배치할 때는 "상대가 무언가를 경계하며 다음 움직임을 준비했다." 정도만 전달한다. 실제로 발동해 공개되는 시점에는 "다시 한번 손 대기만 해 봐... 아주 가만두지 않을 테야..!!"와 같은 카드별 생각을 전달하고, 행위자 정보는 사건 데이터에서 별도로 지정한다.

매 세션마다 무작위 환경 효과가 부여될 수 있으며 전투에 영향을 주는 고유 효과를 지닌다. 환경 효과는 동시에 두 가지가 부여될 수 없다.
아래 환경과 효과는 알파 테스트를 위한 임시 아이디어이다.
예시
* 한산함: 플레이어가 카드를 사용할 때마다 은폐 -1
* 지옥철: 접근 또는 회피 카드로 인한 저항/은폐 변동치의 절대값이 1만큼 감소하며 절대값이 0인 경우에는 그대로 유지
* 우천: 캐릭터의 시작 저항에 +10
* 어두운 조명: 모든 카드로부터 1의 은폐 피해 감소

한 세션이 끝나면 다음 중 하나를 선택할 수 있다.
* 무작위 퍽 3개 중 하나를 획득
* 보유한 카드 중 최대 두장을 제거
* 카드 드래프트(무작위 카드 3장이 나타나고 그 중 하나를 선택)를 3회 진행
* 고성능의 퍽 또는 카드를 랜덤하게 하나 획득

초기 덱 크기는 10장, 최소 덱 크기는 10장, 알파 테스트의 최대 덱 크기는 20장으로 제한한다. 동일한 카드는 최대 두장까지만 보유할 수 있다.
최대 덱 크기에서 새로운 카드를 획득하려면 기존 카드와 교체해야 한다. 최대 덱 크기는 테스트 결과에 따라 조정될 수 있다.
플레이어는 퍽을 최대 세개까지만 보유할 수 있으며 네번째 퍽을 획득할 때는 기존 퍽 하나와 교체한다.

캐릭터의 저항은 기본을 30으로 하되 캐릭터에 따라 저항 수치가 다를 수 있다.
플레이어의 은폐는 30으로 시작하며 얻게되는 퍽에 따라 변경될 수 있다.

# 데이터와 저장

카드, 특징, 환경과 캐릭터 같은 정적 게임 정의는 Lua 테이블로 작성한다. 조건과 효과에는 실제 Lua 함수를 사용할 수 있지만 함수는 상태를 직접 변경하지 않고 구조화된 효과 목록을 반환한다. 공통 전투 엔진이 그 목록에 환경·퍽·특징 보정을 적용하고 상태, 이벤트 로그와 LLM 사건을 함께 갱신한다.

진행 상태와 세이브 데이터는 함수가 없는 JSON 직렬화 가능한 값만 저장한다. 카드 정의를 저장 상태에 복사하지 않고 안정적인 카드 ID와 변화 가능한 상태만 기록한다.

스키마 키, 카드 ID, 행동 태그와 메커니즘의 내부 식별자는 ASCII를 사용한다. 카드명, 설명, UI 표시명과 LLM 묘사는 한글을 사용한다.

사용자에게 보여줄 카드 설명은 자신의 행동 태그와 모든 메커니즘을 문장 안에서 직접 설명한다. 태그 위치는 `::tag[contact]::`처럼 ASCII 내부 ID를 사용한 토큰으로 표시한다. 이 토큰은 화면 표시용일 뿐이며 실제 판정은 `actionTag`, `mechanisms`와 효과 함수를 기준으로 한다.

# UI

화면별로 `battleView`, `deckView`, `collectionView` 같은 구조화 채팅 변수 하나를 사용한다. 고정 정보는 `dict_element`, 손패·덱·도감 같은 가변 목록은 CBS 반복문으로 표시한다.

View 생성기는 카드 설명의 태그 토큰을 텍스트와 태그 조각으로 분리한다. HTML/CBS는 태그 조각을 행동·메커니즘 종류가 구분되는 인라인 `span`으로 렌더링하고, 태그가 아닌 문장은 이스케이프해 표시한다. DB 설명에 원시 HTML을 직접 기록하지 않는다.

전투 UI는 항상 가장 최근 LLM 출력 아래의 사용자 메시지 하나만 유지한다. 정상 출력이 도착하면 이전 UI 메시지를 제거하고 새 출력 아래에 갱신된 UI를 추가한다. UI 메시지는 모델 요청에서 제외한다.
